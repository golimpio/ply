# Review of 8334d49 (M1 core and M3 streaming)

Independent review requested by the owner. Two read-only reviewers (Sonnet) worked
on a `git archive` snapshot of 8334d49. rare-tiger re-ran every reproduction and traced
each finding in the code before listing it here. Only BLOCKING and SHOULD findings are
listed.

## Part 1: M1 core (scanner, store, API, auth, playback, main)

All four findings are in `internal/library/scanner.go` (`scanRoot` / `removeMissing`).
Each one breaks the DESIGN guarantee "unmounted/permission errors never wipe the
library".

### B1 BLOCKING: a symlinked root deletes all its rows
- **Where:** `scanner.go:206` (`os.Stat(root)`) against `:248` (`filepath.WalkDir(root, …)`).
- **Defect:** `os.Stat` follows the symlink, so the IsDir check passes. `WalkDir` Lstats
  the root and does not descend into a symlink. The walk "completes" with 0 files and 0
  errors, so `removeMissing` deletes every row whose `Root == root`, and `Scan` returns nil.
- **Reproduced:**
  - An indexed root replaced by a symlink to the moved directory goes from 1 item to 0
    (err=nil).
  - `-media /link-to-dir` indexes nothing, with no error shown.
- **Fix:** resolve the root with `filepath.EvalSymlinks` before walking (keep storing rows
  under the configured root, but walk the resolved path), or walk `root + "/"`. Add a test
  for each case.

### B2 BLOCKING (reviewer said SHOULD; raised because M5 progress rows can't be rebuilt): an unmounted mountpoint wipes the root
- **Where:** `scanner.go:295-299`.
- **Defect:** on Linux an unmounted NAS leaves an empty mountpoint directory. The root
  exists and the walk has no errors, so every row for that root is deleted.
- **Reproduced:** 2 items become 0, err=nil. On macOS `/Volumes/X` vanishes when
  unmounted, so this case is already safe there.
- **Fix:** when the walk saw 0 video files but the DB has rows for that root, skip removals
  and report an error ("root is empty; refusing to remove N items"). Optionally also refuse
  a single scan that would remove more than ~50% of a root's rows.

### B3 SHOULD: a dangling file symlink is treated as a raced delete
- **Where:** `scanner.go:263-269`.
- **Defect:** an `ErrNotExist` from `os.Stat` is ignored. In a symlink-farm root whose
  target drive is unmounted, the indexed items are deleted and `LastError` stays empty.
- **Reproduced:** 1 item becomes 0, err=nil, lastError="". The existing test only covers a
  dangling link that was never indexed.
- **Fix:** when `d.Type()&fs.ModeSymlink != 0` and Stat returns `ErrNotExist`, do
  `walkErrors++`. Keep ignoring `ErrNotExist` for regular entries.

### B4 SHOULD: rows keep the root they were first indexed under
- **Where:** `scanner.go:176` (one `FileStates` snapshot), `:276` (unchanged files are
  skipped), and `:303-312` (removal is gated on `st.Root == root`).
- **Defect:**
  - Rows of a `-media` root that has been removed are never pruned, so they return 404 on
    `/file` forever.
  - With nested roots (`/m` and `/m/movies`), the first scan probes files twice because of
    the stale snapshot. Removing the inner root orphans rows that the outer root still
    walks.
- **Reproduced:** `TestRevOrphanRoot` and `TestRevOverlap` in the reviewer's copy.
- **Fix:** re-root rows seen under a different configured root. Prune rows of roots that
  are no longer configured only when `os.Lstat(path)` returns `ErrNotExist`.

### Test gap, SHOULD: the SPA path-traversal test is vacuous
- **Where:** `internal/api/api_test.go:839` ("path traversal stays inside the UI").
- **Why it proves nothing:** the `fstest.MapFS` fixture has nothing outside it to leak, and
  the test only checks that the body lacks "root:", with no positive control.
- **The handler itself is safe:** it serves only from `fs.FS`, with a cleaned path.
- **Make it real:** serve `os.DirFS(tmp/ui)` with a secret file beside it, request
  `/../secret`, `/%2e%2e/secret` and `/..%2fsecret`, and first assert that `/index.html`
  returns 200.

### Optional regression guards (these pass today)
- Add HEAD, bare `/api` and `%2F` rows to the auth matrix.
- Send a token containing `&`, `+` or a space through `withToken`.
- Have the zero-copy test go through `New()` rather than `middleware()`.

### Checked, no defect
- **Auth:** 25 bypass variants tried; none bypassed it.
- **withToken:** joins with `&` when a query already exists.
- **File serving:** the path comes only from the DB, and Range/ETag go through
  `ServeContent`.
- **Middleware:** doesn't wrap the ResponseWriter, so sendfile is kept.
- **Store:** transactional upsert, CASCADE deletes, and a DSN that opens with `?#%&+ü` in
  the data path.
- **Decide:** every branch matches the spec.
- **Name parsing:** 28 adversarial names behave sensibly.
- **main.go:** shutdown order is correct.
- **Suites:** race and integration PASS.
- **Mutants KILLED:** the `walkErrors` gate and the `st.Root` filter.

## Part 2: M3 streaming (`internal/stream`, `internal/api/stream.go`)

The reviewer judged against `docs/NOTES.md`; the deliberate deviations there
(fragment-per-keyframe, `PLY_STREAM_IDLE`) are not reported. rare-tiger traced S1–S4 in
the code. S5 is traced only.

### S1 BLOCKING: seeking back into a pruned range while ffmpeg is running gives 504
- **Where:** `session.go:337` (the `ensureGOP` restart condition) together with the prune
  at `:261-265` (`keepBehind = 3` segments).
- **Defect:** for a missing GOP with `r.start <= g < r.next` (already pruned), every restart
  condition is false. A paused run is resumed, but ffmpeg is already past that GOP and will
  never rewrite it. The request waits `WaitTimeout` (30 s) and returns 504. hls.js retries
  and gets the same.
- **When it happens:** the player keeps 60 s of back buffer (`backBufferLength: 60`) but
  the server keeps only about 18 s, so any seek back past about 18 s that falls outside the
  browser buffer hits this. Safari's native player does too.
- **Reproduced:** fake ffmpeg, open segments 0..9, wait for the prune, `OpenSegment(1)`.
  Result: timeout with `starts=1` (no restart happened).
- **Fix:** add `|| g < r.next` to the restart condition. Once the missing-file check at the
  top of the loop has failed, a GOP below `next` can never reappear.
- **Test:** open 0..9, wait for the prune, open 1, and expect success with 2 starts.

### S2 BLOCKING: concurrent far-apart requests kill each other's ffmpeg forever
- **Where:** `session.go:330-343` (`ensureGOP`), and `OpenInit` at `:446`.
- **Defect:** restarts are not arbitrated. Every waiter that finds its GOP outside the run's
  window kills the run and starts its own, and a new run gets no grace period. Two
  overlapping requests for distant segments therefore keep replacing each other; the
  `replaced` flag only suppresses the error.
- **When it happens:** a prefetching native player, an AirPlay or Cast receiver, or a quick
  double seek.
- **Reproduced:** real ffmpeg, `OpenSegment(0)` and `OpenSegment(100)` at once on a 1500 s
  file. Both timed out after 12 s, with 961 runs started (about 80 ffmpeg spawns per
  second).
- **Fix:** latest request wins (restart only when `idx == s.lastSeg`; older waiters just
  wait or time out). Also give a fresh run a minimum lifetime, or until its first fragment
  appears, before it can be replaced.
- **Test:** concurrent `OpenSegment(0)` and `OpenSegment(far)`. Expect the later one to
  succeed and the number of starts to stay bounded.

### S3 SHOULD: ffmpeg survives a crash of the server, and a stopped one stays stopped forever
- **Where:** `proc_unix.go:16-25` (`Setpgid`) and `manager.go:150-178`.
- **Defect:** the separate process group means a `kill -9`, OOM kill or panic of the server
  leaves ffmpeg running. A throttle-paused one stays in state T forever, holding the source
  file and its segments. `removeStale` at the next start deletes the directory but never
  kills the process.
- **Where it matters:** launchd kills only the job's own process group, so this bites on
  macOS. systemd's default cgroup kill mostly covers Linux.
- **Reproduced:** in the reviewer's probe (SIGKILL the holder; the child survives in state
  T after removeStale).
- **Fix:** write the ffmpeg pgid to `<sid>/ffmpeg.pid`. In `removeStale`, send SIGCONT then
  SIGKILL to recorded pgids before removing the directory. Optionally also set `Pdeathsig`
  on Linux.

### S4 SHOULD: `removeStale` wipes whatever the temp root points to
- **Where:** `manager.go:164-178`.
- **Defect:** `ReadDir` follows a symlinked `TempRoot`, and every entry that is not a live
  pid is removed, including non-numeric names. The root is the predictable
  `os.TempDir()/ply-sessions`, with no ownership check.
- **Risk:** on a multi-user Linux host with a shared `/tmp`, another user can pre-create it
  as a symlink to a directory the ply user owns. On macOS `TempDir` is per-user, so this
  doesn't apply.
- **Reproduced:** a symlinked root had its target's files deleted.
- **Fix:** `Lstat` the root and refuse a symlink or a foreign owner. Create it `0700` and
  verify the uid. Remove only entries that parse as a pid.

### S5 SHOULD (traced, not run in a browser): a paused player fails after the 60 s idle expiry
- **Where:** session idle stop (`session.go:241-244`) and `web/src/components/Player.svelte`
  (the 404 retry handling around `startLoad`).
- **Defect:** hls.js stops fetching once its buffer is full. After a pause longer than the
  idle timeout the session is gone, the next segment request returns 404, three
  `startLoad` retries follow, and then "Stream error".
- **Fix:** on a 404 for a session URL, re-POST `/playback` with `startSec` set to the current
  position and resume. A natural fit for the M5 `PlayerControls` wiring. Alternatively,
  treat a recent playlist hit or a heartbeat as activity.

### Tests that can't fail (reviewer's mutants, run in its copy)
- **Mutant A:** no `Setpgid`, and SIGTERM to the pid instead of SIGKILL to the group.
  `TestNoOrphanFFmpeg`, `TestCloseKillsEverything`, `TestIdleTimeoutAndTouch`,
  `TestSeekRestartsFFmpeg` and `TestThrottle` all still pass, because `WaitDelay`'s fallback
  `Process.Kill` hides it; only the timing changes.
  - So "SIGKILL for a stopped process" and "kill the group" are not pinned.
  - Add a fake ffmpeg that spawns a grandchild and SIGSTOPs itself, then assert both are
    gone promptly, well under `WaitDelay`.
- **Mutant B:** `stopRunLocked` never kills.
  - `TestNoOrphanFFmpeg/delete` and `/close` and `TestCloseKillsEverything` still pass.
    They run before throttling pauses ffmpeg, and `Close` cancels the manager context
    anyway.
  - `api/stream_integration_test.go:271` ("no ffmpeg after DELETE") is vacuous: the 30 s
    clip is finished long before the DELETE, and there is no positive control.
  - `TestIdleSessionEndsAndShutdownCleans` checks no process at all.
  - `TestSessionDelete` asserts the count and directory, not that the process died.
- **Genuinely pinned:** fragment completeness, the idle kill of a SIGSTOP'd run, the seek
  restart count, `-ss` and start-number, the session limit, stale-directory cleanup, and
  the token and filename matrices.

### Checked, no defect
- **Kill path:** `Cancel` sends SIGKILL to the group, which works on a stopped process.
  `WaitDelay` is set.
- **Segment serving:** only fully tiled moof+mdat files are served.
- **Path handling:** `ValidName` is anchored, so there is no traversal. Session ids are
  96-bit random.
- **Token and headers:** the token is rewritten into playlist URIs, and the cache headers
  are correct.
- **Locking and suites:** lock ordering is consistent. race, integration and `-count=3`
  runs all PASS, and `go vet` is clean.

## Fixes

Each fix has a test that failed before it (checked by running the test against the old code,
or against a mutant of the new code). Not committed.

- **B1 fixed.** `scanRoot` walks `filepath.EvalSymlinks(root)` and maps paths back under the configured root. Tests: `TestSymlinkedRootDoesNotWipeLibrary` (1 root replaced by a symlink: the library emptied before), `TestFreshLibraryFromSymlinkedRoot` (indexed nothing before).
- **B2 fixed.** A walk that finds no video files while the DB has rows for that root removes nothing and returns an error ("refusing to remove N items; is the volume mounted?"). Test: `TestEmptyRootDoesNotWipeLibrary` (wiped 2 items, err=nil, before). The optional ">50% of a root" guard is not implemented; a root that loses every file is now never synced until a file reappears or the root is dropped from the configuration (`TestScanCancelledDoesNotRemoveItems` keeps a second file for its positive control).
- **B3 fixed, narrower than suggested.** A dangling file symlink counts as a walk error (blocks removals, sets `LastError`) only when that path is already indexed; a never-indexed one is still ignored, so the existing "dangling link is not an error" test stands. Test: `TestDanglingSymlinkOfIndexedFileBlocksRemovals` (deleted the item, err=nil, before).
- **B4 fixed.** A file belongs to the configured root that already holds its row, else the first root to reach it (`owners` map, so nested roots probe once and do not flap). Rows of a root that is no longer configured move to the configured root that reaches the file (`Store.SetItemRoot`), and are deleted only when `Lstat(path)` says `ErrNotExist` (and not inside a root that failed to scan this time). Rows whose file still exists stay. Tests: `TestRowsOfRemovedRootArePrunedWhenTheirFilesVanish`, `TestNestedRoots` (3 probes for 2 files, rows never pruned, before).
- **SPA traversal test fixed.** `TestSPAPathTraversal`: `os.DirFS` with a secret beside the UI directory, positive controls (`/`, `/index.html` via redirect, assets, deep file, fallback, and a handler rooted one level up that does serve the secret), 12 probe forms (`/../x`, `/%2e%2e/x`, `/..%2fx`, ...) against the handler directly and over HTTP with and without following redirects, on `os.DirFS` and on a lax filesystem that would really leak. A mutant handler (no `Clean`, no `ServeFileFS`) is caught. Note that `http.ServeFileFS` and `fs.ValidPath` are two more layers behind `Clean`, so dropping `Clean` alone is an equivalent mutant.
- **S1 fixed.** `beyondRunLocked` restarts when a GOP below `r.next` is gone from disk (stat under the lock). Test: `TestSeekBackIntoPrunedRangeRestartsFFmpeg` (timeout with 1 start before; needs 2 starts, `-start_number 3`).
- **S2 fixed.** Segment requests get an arrival number; only the newest request still in progress may replace a live ffmpeg, older ones wait (and take over, or time out, once newer ones finish). No minimum run lifetime was added: restarts are now bounded by the number of requests. Test: `TestConcurrentFarRequestsDoNotKillEachOther` (140 starts before, at most 5 now, both requests served).
- **S3 fixed, with a correction.** Each session directory gets `ffmpeg.pid` (pgid and program); `removeStale` kills recorded groups (SIGCONT, SIGKILL) whose leader's command line still contains the program name, so a reused pid is left alone. Tests: `TestKilledServerLeavesNoFFmpeg` (SIGKILLs a helper process running a manager; the orphan survived before), `TestStalePidFileOfAnotherProgramIsIgnored`. Correction: a *stopped* ffmpeg whose parent dies does not stay in state T; the kernel sends SIGHUP and SIGCONT to a newly orphaned group with stopped members, and ffmpeg exits on SIGHUP (a fake did). The leftover that survives is a running one (a long transcode), which is what the test uses. `Pdeathsig` not added.
- **S4 fixed.** `prepareRoot` Lstats the root: refuses a symlink, a non-directory or a foreign owner, creates it 0700 and tightens a too-open one of ours; `removeStale` only touches entries named like a pid. Tests: `TestSymlinkedTempRootIsRefused` (deleted the target's files before), `TestTempRootOwnerIsChecked`, `TestTempRootIsCreatedPrivate`; `TestStaleDirsRemovedAtStartup` now expects non-pid names to stay. `NewManager` returns an error, so `ply` refuses to start with an unsafe temp root (main unchanged).
- **S5 fixed in `Player.svelte`, verified in Chrome.** A network error answered 404 (the first hls.js error, not the fatal one half a minute later) or a native-HLS network error starts a new playback at the current position, at most twice in a row (reset on `canplay`); if the restarted session fails the same way the player stops with an error instead of hanging. Logic in `web/src/lib/session.ts`, vitest table test `web/src/lib/session.test.ts` (`npm test`). Server side of the contract: `TestExpiredSessionAnswers404`. Live check with `-stream-idle 5s`, pause 9 s, seek 70 s ahead: before, hls.js asks for the dead segment seven times and stalls; after, a new session is created and playback resumes within 0.3 s (details in `2026-11-02-review-art-web.md`). `npm run check` and `npm run build` pass.
- **Mutant A (no Setpgid / SIGTERM) and B (`stopRunLocked` never kills): fixed.** `TestStoppedFFmpegIsKilledWithItsGroup` uses a fake ffmpeg with a helper process that SIGSTOPs itself, and checks Delete, idle expiry, Close and a seek: all return well under `WaitDelay` and leave neither process. Both mutants fail all four subtests; so does "SIGKILL to the pid only". `TestSessionDelete` now checks the process died; the vacuous DELETE check in `TestHLSEndToEnd` is replaced by `TestDeleteKillsAThrottledFFmpeg` (25 minute clip, ffmpeg stopped by the throttle, positive control).
- **`TestIdleSessionEndsAndShutdownCleans` flake fixed at the source.** `Manager.Delete` took the session out of the map before killing ffmpeg and removing the directory, so `Count()==0` came too early. `Count()` (and the session limit) now include sessions being stopped. The test also uses a live stopped ffmpeg and checks shutdown. `TestCountDropsOnlyWhenTheSessionIsGone` (unit) and a `Count()` mutant reproduce the old failure every time.
- **Optional regression guards (HEAD/`/api`/`%2F` auth rows, `&+ ` tokens, zero-copy through `New()`): not done.**
