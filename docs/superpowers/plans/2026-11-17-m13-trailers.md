# M13 Trailers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Trailers become files in the library (both Plex layouts), downloaded on demand by a native Go YouTube/Vimeo downloader, and played by ply's own player on web, iOS and tvOS.

**Architecture:** A trailer is an `items` row of kind `trailer` with no `title_id`; its owner is resolved on read from where it sits (`owner_dir`, parsed name, show). A `trailer.download` job (orchestrated by `internal/trailers`, downloading with `internal/trailerdl`) writes Plex-named files into the film's or show's folder and indexes them at once. `GET /api/titles/{id}/trailers` lists local trailers, reports and triggers the download; clients play `local[0].itemId` in the existing player.

**Tech Stack:** Go (stdlib, SQLite via the existing store), ffmpeg/ffprobe, Svelte 5 + TypeScript, SwiftUI (iOS 17/tvOS 17).

**Spec:** `docs/M13-TRAILERS.md` (read it first; this plan argues from it).

## Global Constraints
- Native only: no yt-dlp binary, no JS runtime, no new Go module dependency. ffmpeg is the only external tool (`stream.ResolveFFmpeg`).
- Trailer kind string: `"trailer"` (`store.KindTrailer`). Job kind: `"trailer.download"`, key `"title:<id>"`.
- Download quality: video ≤ 1080p, H.264 (`avc1`) preferred at equal height; audio AAC (`mp4a`, itag 140) preferred; output MP4 `+faststart`.
- YouTube client: `visionos` (`clientName` `VISIONOS`, `X-YouTube-Client-Name: 101`, `clientVersion` `1.02`, UA `Mozilla/5.0 (Macintosh; Intel Mac OS X 15_7_3) AppleWebKit/605.1.15 (KHTML, like Gecko) Version/26.0 Safari/605.1.15`, `osName` `visionOS`, `osVersion` `26.5.23O471`, `deviceMake` `Apple`, `deviceModel` `RealityDevice17,1`).
- Range chunks: 10 MiB randomised to 95–100 %. Media requests use a desktop Chrome UA.
- Default names: own folder `<folder>/<folder name>-trailer.mp4`; shared folder `<folder>/<Title> (<Year>)-trailer.mp4` (no year: `<Title>-trailer.mp4`); show `<show folder>/<show folder name>-trailer.mp4`. `/ \ : * ? " < > |` → space; NFC. Never overwrite.
- Temp: `<Data>/tmp/trailers/<job id>/`; library writes via `.<name>.part` + fsync + rename.
- Failure memory: not-available kinds 24 h; others 5 min doubling to 1 h (metadata's constants, exported, not copied).
- Online lookups off: no download is queued; a queued one whose turn comes with lookups off fails at once ("Online lookups are off"). Local trailers still listed and playable.
- Trailers never get progress, watched marks, `title_id`, matching, subtitle pre-extraction.
- Strict DRY (AGENTS.md): web uses existing tokens/classes (`.btn`, `.spinner`, `Menu.svelte`); iOS uses `DetailActionButton` if present at HEAD, else the existing button style.
- Every fix has a test that fails without it (mutant-checked); an absence assertion has a positive control.

## Review Focus
1. A film folder holding two different films plus one `-trailer` file (shared layout below the root): the trailer must attach to the film whose parsed title/year matches, not to both. → Task 3 test `TestTitleTrailersSharedSubfolder`.
2. A NAS folder that is read-only or unmounted mid-download: the job fails with words, no `.part` file is left behind. → Task 8 test `TestDownloadReadOnlyFolderLeavesNothing`.
3. Opening the same page twice quickly (two clients, or web + iPhone): exactly one job. → Task 9 test `TestTrailersTriggerDedupWhileRunning`.
4. A title whose files are a film in `Movies/` *and* a stray copy in another root: destination is the first (lowest id) item's folder, and the trailer still attaches. → Task 8 test `TestDestinationVersionsInTwoFolders`.
5. YouTube answers 403 mid-download (expired or IP-bound URL): job fails cleanly, temp dir removed, next trailer in the list tried. → Task 7 test `TestFetchFallsBackToNextVideoOn403`.
